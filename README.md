# Trânsito BH — where, when and whom traffic hurts in Belo Horizonte

[Português](README.pt-BR.md) · **Live site:** <https://dias0202.github.io/transito-bh/>

An open-data diagnosis of road traffic in Belo Horizonte (Brazil) and its metro region, plus statistical and
machine-learning models evaluated against honest baselines. Deliverables: a bilingual working paper (Quarto,
`paper/`), a scrollytelling site (`site/`, published from [`Dias0202/transito-bh`](https://github.com/Dias0202/transito-bh))
and a reproducible Python package (`src/bhtraffic`).

> Status: working draft (paper v0.1, 2026-10-16). Crash data through August 2026. Sections of the paper marked
> *planned* describe methods, not results. See [docs/roadmap.md](docs/roadmap.md).

## Findings

Numbers below come from `paper/en/index.qmd`, generated by `bhtraffic.export.site` and `bhtraffic.viz.figures`.

- **38 injury crashes per day** in 2025 (13,887), the most since 2014; 148 fatal crashes.
- **75%** of injury crashes involve a motorcycle; motorcyclists and pedestrians are **80%** of deaths (2020–2024).
  At radar sites, motorcycles are 13.2% of passages but are involved in 76.6% of nearby crashes:
  a crash **rate ratio of 21** per passage (95% CI 18–25, bootstrap over locations; area-level exposure, not per-trip risk).
- Weekday peaks at **7:00 and 18:00**; the worst hour of the week is **Wednesday 18:00**.
- Rain: **+13.6%** crashes per rainy hour (RR 1.136, 95% CI 1.10–1.17); the **first rain after 72 dry hours** adds
  another **+19%** (RR 1.19, 1.09–1.30). Holidays −31% (mostly less traffic). Football matches: no detectable effect.
- **Speed bumps: about 21% fewer injury crashes** within 100 m, net of a placebo window (×0.79, 95% CI 0.72–0.87).
  **Speed cameras:** no detectable effect at 150 m (×1.00, 0.92–1.10).

## Methods

| Question | Design | Result |
|---|---|---|
| Crash risk per H3 cell × weekday × hour (72,072 cell-hours) | LightGBM with Poisson loss, history-only features (v0) and + 14 OpenStreetMap road features fixed before looking at the test year (v1). Features use only years before the target year: training target 2024 (2019–2023 history), **test target 2025** (2020–2024 history). Baselines: 3-year cell-hour mean; cell rate × citywide hourly profile. Cell-block bootstrap (500 replicates). | Risk is concentrated: 5% of cell-hours hold 23% of crashes. LightGBM fits better on deviance (Δ 95% CI [−0.020, −0.011]) but **ties the transparent baseline on the prioritisation metric** (top-5% capture Δ [−0.2, +0.9] pp); on 2024 it tied on both. OSM features add nothing. Reported as such. |
| Holidays, matches, rain | Hourly Poisson GLM (137,328 hours, 2011–Aug 2026) with weekday × hour, month, year and pandemic fixed effects; standard errors clustered by day | Rate ratios with 95% CIs (above) |
| Speed and red-light cameras | Site × month Poisson panel with site and month fixed effects, SEs clustered by site; event study of the Nov 2025 mass removal | No detectable effect. The removal event study rejects parallel pre-trends (p = 0.005) and is labelled fragile |
| Speed bumps (2,627, 2013–2025) | 12 months after vs 12 before, relative to the citywide total (ratio of ratios), with a placebo window one year earlier to measure regression to the mean; bootstrap over operational projects | ×0.82 raw, placebo ×1.04 [0.99–1.09], **net ×0.79 [0.72–0.87]** |
| "What if" scenarios | Effects measured above, or explicitly labelled assumptions (e.g. the Power Model for speed), propagated by Monte Carlo (5,000 draws; 90% intervals) | e.g. 100 speed bumps at eligible high-crash local streets: 118 (81–153) crashes avoided per year |
| Microsimulation | SUMO pilot of Av. Antônio Carlos, demand fitted to radar counts | **Not calibrated yet** (best GEH 41 vs target < 5); no scenario results are published |

Design choices were fixed before results were looked at, null effects are reported as results, and every scenario
states whether its effect was measured here or assumed.

## Layout

```
src/bhtraffic/
  config.py              paths (local vs Colab/Drive), CRS, constants
  collect/               stdlib-only collector: TomTom Routing, PBH bus GPS (HERE blocked: zero-cost)
  ingest/                PBH CKAN download, crash tables (column aliases, coordinate fix, placeholder geocodes, H3),
                         BHTrans radar counts, monthly crashes 2016→, enforcement history, calendar, INMET rain
  geo/                   corridors (data/corridors.toml), OSM road features per H3 cell
  models/risk.py         crash-risk model (H3 × weekday × hour), baselines, bootstrap, SHAP
  models/temporal.py     holiday / match / rain effects (Poisson GLM, day-clustered SEs)
  models/enforcement.py  cameras (site × month FE Poisson, Nov 2025 removal) and speed bumps (before/after + placebo)
  analysis/              congestion (radar speed index vs night free flow), motorcycle exposure
  sim/                   Monte Carlo "what if" scenarios, SUMO pilot
  viz/, export/          paper figures (PT/EN), aggregated JSON for the site
notebooks/               Colab setup, ingestion, EDA, radars, collector monitor, risk model
paper/                   Quarto: pt/ and en/, shared figures/
site/                    Vite + TypeScript + GSAP + MapLibre scrollytelling (see site/DESIGN.md)
tests/                   parsers, crash-data fixes, models, scenarios, free-tier budget
```

## Run

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[geo,viz,ml,dev]"
pytest
python -m bhtraffic.collect.run --dry-run                  # collector on fixtures, no network
```

CI installs the pinned test environment from `requirements/ci.txt` (compiled from `requirements/ci.in` with
`uv pip compile --universal --python-version 3.11`) and runs `pytest`.

Pipeline, in this order (all sources free; outputs in `data/processed`, or Drive on Colab):

```bash
python -c "from bhtraffic.ingest import sinistros; sinistros.build()"   # 1. yearly crash tables 2011-2024
python -m bhtraffic.ingest.recentes                        # 2. monthly crashes 2016 -> now, enforcement, speed bumps
python -m bhtraffic.ingest.calendar                        # 3. holidays + Série A matches
python -m bhtraffic.ingest.inmet 2011 2026                 #    hourly rain (INMET A521)
python -m bhtraffic.geo.osm                                #    OSM road features per H3 cell
python -m bhtraffic.models.risk                            # 4. models
python -m bhtraffic.models.temporal
python -m bhtraffic.models.enforcement
python -m bhtraffic.export.site                            # 5. site/public/data/*.json
```

Site: `cd site && npm install && npm run dev` (build with `npm run build`, static output in `site/dist`).
Paper (Quarto ≥ 1.4, PDF via Typst): `cd paper && quarto render`.

## Collector and zero-cost policy

A GitHub Actions cron collects bus GPS (every 15 min at weekday peaks, hourly otherwise) and TomTom Routing travel
times (every 30 min at weekday peaks). It needs the secrets `TOMTOM_API_KEY` and `RCLONE_CONF`
([docs/setup_api_keys.md](docs/setup_api_keys.md), [docs/setup_rclone.md](docs/setup_rclone.md)) and only runs on a
schedule when the repository variable `COLLECTOR_ENABLED=true` is set.

The project must never incur a charge: every service stays under 75% of its free tier (`src/bhtraffic/collect/budget.py`),
providers that require a card without a hard spending cap are blocked (HERE), and `tests/test_budget.py` expands the
workflow crons over real calendars and fails if the worst-case month would exceed any free tier.

## Data

Raw and processed data live on Google Drive, never in git. Only aggregates are published, plus one bus-position
snapshot without vehicle or line IDs (`site/public/data/bus.json`). Data quirks and fixes: [docs/data_audit.md](docs/data_audit.md).
